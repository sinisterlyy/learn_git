/ part 01ทำไมต้องใช้ Git?

ลองนึกถึง "ปุ่ม Save" ของชีวิตจริง — บันทึกได้ทุกเวลา ย้อนกลับได้ทุกจุด เห็นว่าใครแก้อะไร เมื่อไหร่

ปัญหาที่ Git แก้ได้

• ลบไฟล์ผิด → ย้อนกลับได้
• ไม่รู้ว่าโค้ดเสียตอนไหน → ดู history ได้
• หลายคนแก้ไฟล์เดียวกัน → ไม่ทับงานกัน
• อยากลองทำ feature ใหม่ → แยก branch ทำ ถ้าพังไม่กระทบของหลัก

Git ≠ GitHub

เข้าใจให้ถูก

Git = ระบบบันทึกการเปลี่ยนแปลง ทำงานบนเครื่องคุณ (offline ได้)

GitHub = เว็บไซต์ที่เก็บ Git repo ออนไลน์ ไว้แชร์กับทีม

เปรียบเทียบ: Git = Microsoft Word · GitHub = Google Drive

Real talk

ในงานจริงที่ Alumet

โค้ด Django, scripts, configs ของระบบทั้งหมดเก็บใน Git — ถ้าใช้ไม่เป็น = ทำงานทีมไม่ได้

/ 10 minติดตั้งและ Config

  1. ติดตั้ง Git

    Windows: git-scm.com/download/win
    macOS: brew install git

  2. เปิด VS Code → Terminal

    เมนู View → Terminal (หรือ Ctrl + `)

  3. เช็คว่าติดตั้งสำเร็จ

    พิมพ์ git --version ต้องเห็นเลขเวอร์ชั่น

  4. บอก Git ว่าคุณเป็นใคร

    ทำครั้งเดียวพอ ต่อไปทุก commit จะมีชื่อคุณ

$ git --version git version 2.43.0 $ git config --global user.name "Somchai Jaidee" $ git config --global user.email "somchai@alumet.co.th" # ตั้ง default branch เป็น main $ git config --global init.defaultBranch main # เช็คว่าตั้งถูกหรือยัง $ git config --list
⚠ สำคัญ

ใช้ email เดียวกันกับที่สมัคร GitHub ถ้าใช้คนละ email ระบบจะไม่นับว่าเป็น contribution ของคุณ

/ part 023 พื้นที่ของ Git

เข้าใจอันนี้ — ที่เหลือง่ายหมด

01

Working Dir

ไฟล์ที่คุณกำลังแก้อยู่ใน VS Code

→git add
02

Staging Area

ของที่เตรียมจะ commit แต่ยังไม่บันทึก

→git commit
03

Local Repo

บันทึกถาวรในเครื่องคุณ มี history

→git push
04

GitHub

เก็บออนไลน์ แชร์กับทีม

Analogy: ส่งของไปไปรษณีย์

Working dir = ของในบ้านคุณ
Staging = ของที่ใส่กล่องเตรียมส่งแล้ว
Local repo = ส่งเข้าคลังของไปรษณีย์
GitHub = ส่งไปยังปลายทาง

คำสั่งหลัก 3 ตัว

จำ 3 คำนี้พอ ใช้ทุกวัน:

  • git add — เอาไฟล์เข้า staging
  • git commit — บันทึกลง local repo
  • git push — ส่งขึ้น GitHub

/ hands-on #1สร้าง Repo แรก

ทำตามทุกบรรทัด → จะมี repo จริงในเครื่อง

  1. สร้างโฟลเดอร์ใหม่

    ตั้งชื่อ my-first-repo

  2. เปิดด้วย VS Code

    File → Open Folder

  3. เปิด Terminal ในโฟลเดอร์นั้น

    Terminal → New Terminal

  4. เริ่ม Git

    พิมพ์ git init — จะมีโฟลเดอร์ .git ซ่อนอยู่

  5. สร้างไฟล์ทดสอบ

    สร้าง README.md เขียนอะไรก็ได้

$ mkdir my-first-repo $ cd my-first-repo $ git init Initialized empty Git repository in /Users/you/my-first-repo/.git/ # สร้างไฟล์ทดสอบ $ echo "# My First Repo" > README.md # ดูสถานะ — Git เห็นไฟล์ใหม่แต่ยังไม่ track $ git status On branch main No commits yet Untracked files: (use "git add <file>..." to include) README.md nothing added to commit but untracked files present
git status

คำสั่งที่ต้องพิมพ์บ่อยที่สุด — มันบอก Git กำลังคิดอะไรอยู่ ใช้ทุกครั้งที่งง

Part 02 · Safety net
08 / 14

/ undoถ้าทำพลาดทำยังไง?

Case 1

แก้ไฟล์แล้วอยากกลับ

ยังไม่ได้ add → กลับไปเหมือนเดิม

$ git restore file.txt
Case 2

เผลอ add ผิดไฟล์

เอาออกจาก staging (ไฟล์ไม่หาย)

$ git restore --staged file.txt
Case 3

เขียน message ผิดใน commit ล่าสุด

แก้ message ใหม่ได้ (ถ้ายังไม่ push)

$ git commit --amend -m "ข้อความใหม่"
กฎเหล็ก

อย่าใช้ --force หรือคำสั่งแก้ history ถ้า push ขึ้นไปแล้ว — มันจะกระทบทีม ถ้าไม่แน่ใจ ถามพี่ก่อน

"Git is hard to lose work in — once you've committed."

/ part 03เชื่อมกับ GitHub

  1. สมัคร GitHub account

    ใช้ email เดียวกับที่ตั้งใน git config

  2. สร้าง SSH Key

    เพื่อ push ได้โดยไม่ต้องใส่รหัสทุกครั้ง

  3. เอา public key ไปวางใน GitHub

    Settings → SSH and GPG keys → New SSH key

  4. สร้าง repo ใหม่บน GitHub

    กด "+" มุมขวาบน → New repository
    เลือก Private สำหรับงาน, Public สำหรับ portfolio

  5. เชื่อม local กับ GitHub

    คำสั่งจะอยู่ในหน้า repo ที่เพิ่งสร้าง

# สร้าง SSH key $ ssh-keygen -t ed25519 -C "your@email" Enter file: [Enter ผ่าน] Enter passphrase: [Enter ผ่านได้] # Copy public key $ cat ~/.ssh/id_ed25519.pub ssh-ed25519 AAAAC3Nz... your@email # เอาทั้งบรรทัดไปวางใน GitHub # ทดสอบว่าเชื่อมได้ $ ssh -T git@github.com Hi yourusername! Part 03 · Remote workflow

/ remotePush · Pull · Clone

Push

ส่งของขึ้น GitHub

# เชื่อม remote ครั้งแรก $ git remote add origin git@github.com:you/repo.git # push ครั้งแรก (ตั้ง upstream) $ git push -u origin main # ครั้งต่อไป พิมพ์สั้นๆ ได้ $ git push
Pull

ดึงของล่าสุดลงมา

เมื่อเพื่อนร่วมทีม push อะไรขึ้นไป คุณต้อง pull ลงมา

$ git pull
Clone

เริ่มงานใหม่จาก repo ที่มีอยู่

เข้ามาวันแรกที่บริษัท → clone repo ของทีม

$ git clone git@github.com:alumet/project.git $ cd project $ code . # เปิดใน VS Code
Daily routine

เช้า: git pull
ระหว่างวัน: edit → add → commit
เลิกงาน: git push

/ part 04Branch — ทำหลายอย่างพร้อมกัน

Branch = ก๊อปโลกคู่ขนาน
ทดลองได้เต็มที่ ถ้าพังไม่กระทบของหลัก

ทำไมต้องใช้ branch

• ทำ feature ใหม่โดยไม่กระทบ main
• หลายคนทำงานพร้อมกันไม่ทับกัน
• รีวิวโค้ดก่อน merge เข้า main

กฎ Alumet

อย่า commit ตรงเข้า main — แยก branch เสมอ แล้วเปิด PR

# ดู branch ที่มี $ git branch * main # สร้าง branch ใหม่ + กระโดดเข้าไป $ git switch -c feature/login-page Switched to a new branch 'feature/login-page' # แก้ไฟล์ → add → commit ตามปกติ $ git add . $ git commit -m "Add login form" # push branch ขึ้น GitHub $ git push -u origin feature/login-page # สลับกลับ main $ git switch main # ลบ branch ที่ merge แล้ว $ git branch -d feature/login-page
Naming convention

feature/xxx · fix/444 · hotfix/xxx

git switch · git branch

Part 04 · Pull Request
12 / 14

/ teamworkPull Request — รวมโค้ดเข้าทีม

PR = ขอเอาโค้ดใน branch ของฉัน เข้า main ของทีม — มีคนรีวิวก่อน

  1. Push branch ขึ้น GitHub

    git push -u origin feature/xxx

  2. เข้าหน้า repo บน GitHub

    มันจะขึ้นปุ่ม "Compare & pull request" สีเขียว

  3. เขียนคำอธิบาย

    ทำอะไร, ทำไม, ทดสอบยังไง, screenshot ถ้ามี

  4. Request review

    เลือก reviewer (พี่ในทีม) ทางขวา

  5. แก้ตาม comment

    commit + push ใหม่ → PR อัพเดทอัตโนมัติ

  6. Merge เมื่อได้ approve

    กดปุ่ม Merge → branch รวมเข้า main

PR Description Template
## What เพิ่ม login form หน้า /login ## Why User ขอให้แยกหน้า login ออกจากหน้าหลัก (Jira #123) ## How to test 1. npm run dev 2. เข้า /login 3. ลองใส่ email ว่าง ## Screenshot [แนบรูป]
มารยาทใน PR

PR ขนาดเล็ก รีวิวง่าย ผ่านเร็ว — แยกงานเป็นชิ้นเล็กๆ ดีกว่ารวมก้อนใหญ่
